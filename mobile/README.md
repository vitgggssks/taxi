# РУХ · Android (Flutter)

Мобільний застосунок пасажира **і** водія в одному APK: роль визначається акаунтом,
тож один і той самий застосунок показує або екран замовлення, або робочий екран водія.

## Що вміє

**Пасажир**

- вхід за номером телефону з OTP (реальний флоу `request-otp` → `verify-otp`) або швидкий демо-вхід;
- місто з довідника, пошук адрес по індексу міста, збережені адреси («Мої адреси»);
- до 5 проміжних зупинок, попереднє замовлення (дата + час), коментар водієві;
- послуги: поїздка, доставка посилки (до 20 кг, відправник/отримувач/вага), міжмісто, тверезий водій;
- ціна по кожному класу авто з живого Pricing Engine (нічні/пікові коефіцієнти, опції, промокод, «плюс/мінус»);
- оплата: готівка, картка, баланс; кешбек у бонусах;
- трекінг замовлення: статуси в реальному часі через WebSocket, дані водія й авто, скасування,
  оцінка після поїздки, оплата, «повторити замовлення»;
- історія з фільтрами, гаманець з транзакціями й поповненням, сповіщення, звернення в підтримку.

**Водій**

- онлайн/офлайн (з урахуванням верифікації), передача координат диспетчеру;
- вхідні пропозиції з таймером, ціною, відстанню подачі та раундом; прийняти/відхилити;
- просування статусу: *їду до клієнта → на місці → почати поїздку → завершити*;
- доставка: підтвердження кодами відправника й отримувача;
- заробіток, баланс, комісія, рейтинг, відсоток прийняття.

## Запуск

```bash
cd mobile
flutter pub get

# емулятор Android → хост-машина це 10.0.2.2
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000

# реальний телефон у тій самій Wi-Fi: вкажіть IP компʼютера
flutter run --dart-define=API_BASE_URL=http://192.168.0.10:3000
```

Адресу API можна змінити й у самому застосунку: **екран входу → іконка сервера** або
**Профіль → Зʼєднання → Змінити адресу API**. Вона зберігається між запусками.

## Збірка APK

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
# → build/app/outputs/flutter-apk/app-release.apk
```

У CI (`.github/workflows/android.yml`) те саме робиться на кожен push у `main`, що змінює
`mobile/**`: прогін `flutter analyze` + `flutter test`, збірка APK, артефакт і публікація
в **Releases** (`android-v0.1.0`).

Адреса API для CI-збірки — змінна репозиторію `API_BASE_URL`
(*Settings → Secrets and variables → Actions → Variables*).

## Підпис для Play Store

Зараз release-APK підписується debug-ключем (так генерує `flutter create`), тому його можна
встановлювати на пристрої, але не публікувати. Для продакшену:

```bash
keytool -genkey -v -keystore ~/rukh-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias rukh
```

`android/key.properties` (не комітити) + `signingConfig` у `android/app/build.gradle.kts`,
а в CI — `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` як secrets.

## Структура

```
mobile/lib/
  main.dart              точка входу, сесія, тема
  theme.dart             дизайн-система (кольори, карточки, статуси)
  core/
    api.dart             REST-клієнт (dart:io HttpClient), типізовані помилки
    models.dart          Order, Quote, Offer, DriverProfile — розбір контрактів /api
    session.dart         токен, профіль, адреса API (shared_preferences)
    realtime.dart        WebSocket з автоперепідключенням і підписками на канали
    format.dart          гроші, час, людські підписи статусів
  screens/
    login_screen.dart    OTP-вхід + демо-доступ + вибір сервера
    shell.dart           нижня навігація, що залежить від ролі
    booking_screen.dart  замовлення: адреси, класи, опції, оплата, плюс/мінус
    order_screen.dart    трекінг у реальному часі, скасування, оцінка, оплата
    history_screen.dart  історія з фільтрами
    wallet_screen.dart   баланс, бонуси, транзакції, поповнення
    profile_screen.dart  адреси, сповіщення, підтримка, налаштування
    driver_screen.dart   онлайн/офлайн, пропозиції, статуси, заробіток
  widgets/address_picker.dart
test/smoke_test.dart     7 тестів: розбір відповідей API, формати, WS-URL
```

Залежності: лише `shared_preferences` (локальне зберігання токена й адреси API).
Мережа — стандартні `dart:io` `HttpClient` та `WebSocket`: жодних важких SDK,
що спрощує збірку й аудит.

## Чого поки немає (чесно)

- **Мапа з тайлами** — координати й маршрут показуються текстом; інтеграція Google Maps/MapLibre — наступний крок.
- **GPS у фоні** — «Передати локацію» надсилає точку подачі активного замовлення; фоновий сервіс
  геолокації потребує дозволів і окремого плагіна.
- **Push (FCM)** — токен пристрою API вже приймає (`/api/me/device-token`), але клієнтська частина FCM не підключена.
- **Мультивалютність/локалізація UI** — інтерфейс українською, валюта з тарифу.
- `package:flutter/material.dart` позначений застарілим у Flutter 3.49+ (на користь
  `package:material_ui/material_ui.dart`); міграцію зробимо окремим PR.
