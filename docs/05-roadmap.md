## Ітерація 3 — мобільні застосунки (2–3 тижні)

## Ітерація 5 — операційна зрілість (1–2 тижні)

- [ ] Матриця ролей/прав у UI (модель у БД уже є), 2FA для адмінів.

## Ітерація 6 — юридичне та запуск (паралельно)

- [ ] Публічні оферти, політика конфіденційності, обробка персональних даних (GDPR-сумісність).
- [ ] Договори з водіями/парками, ліцензійні вимоги до перевезень у містах запуску.
- [ ] SLA підтримки, база знань, шаблони відповідей.
- [ ] Пілот у 1–2 містах: контроль диспетчерів, метрики (ETA, % прийняття, cancel rate, NPS).

## Технічний борг, який треба закрити

- `web/app/*.js` — модульний, але без типізації і збірки; для Flutter-клієнтів достатньо, для
  подальшого розвитку вебу — TS + Vite або Next.js.
- Немає e2e-тестів у CI (є ручний Playwright-прогін: вхід → ціна → замовлення → прийняття водієм →
  завершення → оцінка → адмін-розділи).
- Геокодинг — локальний індекс адрес; для нових міст потрібен імпорт/провайдер.
- `lib/db.ts` не має шару міграцій (схема створюється з `schema.sql`), для проду — міграції.
